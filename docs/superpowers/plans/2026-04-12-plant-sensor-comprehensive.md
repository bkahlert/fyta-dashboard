# Plant Sensor Comprehensive Template Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expand `sensor.*_plant` template sensors to carry all displayed plant attributes, then simplify the dashboard script to read directly from `state_attr(entity, '...')` instead of constructing sibling entity IDs in every Jinja2 template.

**Architecture:** Two files change. `scripts/generate-plant-sensors.mjs` gains 8 new attributes per sensor (device_name, scientific_name, picture_url, temperature_state, light_state, nutrients_state, battery, next_fertilization). `scripts/update-main-view.mjs` drops `PFX_MT` entirely and rewrites every card/chip Jinja2 template to read from attributes. The `benutzerbildSlug` (button-card JS) is unchanged — it operates in JavaScript and must keep its existing moisture-entity lookup.

**Tech Stack:** Node.js 22+ native WebSocket, HA WebSocket API, HA template sensor YAML

**HA_TOKEN:** Read from `process.env.HA_TOKEN`

```js
function generateYaml(prefixes) {
  const sensors = prefixes.map(p => [
    `      - name: "${toTitleCase(p)} Plant"`,
    `        unique_id: ${p}_plant`,
    `        state: "{{ states('sensor.${p}_moisture') | float(0) }}"`,
    `        unit_of_measurement: "%"`,
    `        device_class: moisture`,
    `        state_class: measurement`,
    `        attributes:`,
    `          moisture_state: "{{ states('sensor.${p}_moisture_state') }}"`,
    `          device_name: "{{ device_attr(device_id('sensor.${p}_moisture_state'), 'name') }}"`,
    `          scientific_name: "{{ states('sensor.${p}_scientific_name') }}"`,
    `          picture_url: "{{ state_attr('image.${p}', 'entity_picture') }}"`,
    `          temperature_state: "{{ states('sensor.${p}_temperature_state') }}"`,
    `          light_state: "{{ states('sensor.${p}_light_state') }}"`,
    `          nutrients_state: "{{ states('sensor.${p}_nutrients_state') }}"`,
    `          battery: "{{ states('sensor.${p}_battery') | int(0) }}"`,
    `          next_fertilization: "{{ states('sensor.${p}_next_fertilization') }}"`,
  ].join('\n')).join('\n\n');

  return [
    '# FYTA plant sensor bridges — generated by scripts/generate-plant-sensors.mjs',
    '# Place in your HA config packages directory and reload template entities.',
    'template:',
    '  - sensor:',
    sensors,
    '',
  ].join('\n');
}
```

- [ ] **Step 1: Remove the PFX_MT const block (lines 4–9)**

Delete lines 4–9 entirely (the comment + const declaration):

```js
// ── Template prefix expressions ───────────────────────────────────────────────
// PFX_MT: uses the Jinja2 `entity` variable (available in mushroom template card/chip fields)
// Matches sensor.*_plant entities; strips the _plant suffix to get the FYTA sensor prefix.
// Uses [:-6] (suffix strip) rather than split('_plant')[0] because some prefixes contain
// the substring '_plant' (e.g. count_plantula), which would cause split to truncate early.
const PFX_MT = `entity.split('.')[1][:-6]`;
```

```js
const fertChip = (() => {
  const daysCalc =
    `{%- set fert = state_attr(entity, 'next_fertilization') -%}` +
    `{%- set days = ((as_timestamp(fert) - as_timestamp(now())) / 86400) | int if fert not in ['unavailable','unknown','none',''] else 999 -%}`;
  const nutrientsColor =
    `{%- set ns = state_attr(entity, 'nutrients_state') | string -%}` +
    stateColor('ns');
  return {
    type: 'template',
    entity: 'this.entity_id',
    icon: 'mdi:sprout',
    icon_color: nutrientsColor,
    content:    daysCalc + `{{ '' if days > 14 else days | string + 'd' }}`,
    ...MORE_INFO,
  };
})();
```
